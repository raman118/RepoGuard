# Operating RepoGuard

Liveness is dependency-free. Readiness checks migrated database and Redis with bounded Redis timeouts; local mode explicitly permits notification fallback. Production reports unavailable without either required service. Restrict readiness at ingress if topology disclosure matters. PostgreSQL connection timeouts must be supplied in the database URL/driver configuration (for example connect_timeout=5). Run migrations as a release task, never concurrently in API startup.

Authenticated `/v1/metrics` returns only tenant job counts by fixed states, expired leases and retried jobs. Logs emit allowlisted JSON request route templates/status/duration/request UUID and job state/attempt/error code. Header tokens, raw source, URL identifiers and exception messages are not logged. Scan/job UUID correlates ingestion/analysis/persistence; request UUID correlates API calls. Configure logging INFO centrally. Full OpenTelemetry export is deferred until an exporter backend is available; no traces are claimed.

Signed pushes to connected installation/provider identities create a scan and job in the delivery transaction. Replay creates neither a duplicate scan nor job. Deleted refs/tags and unsupported PR events do not run source. Installation lifecycle events invalidate token cache; revoked access fails GitHub closed. History, cancellation and sanitized failure codes are visible in dashboard. API is stateless beyond DB; workers poll durable rows if wakeups fail.

Alert/operator checks: sustained failed jobs, expired leases, nonzero repeated attempts, unavailable readiness and scan queue age indicate action needed. Inspect tenant metrics/history and JSON job IDs; never paste tokens/source into tickets. Restore DB/Redis, restart workers to reclaim expired leases; rescan permanent invalid archives only after repository data changes. Container cleanup failures require a dedicated validator operator to remove only `rg-validation-*` containers after verifying their identities. No alert delivery or external monitoring integration has been configured.

Retention is currently operator managed: private findings/proposal hashes and minimal edited lines persist in PostgreSQL; ephemeral analysis files are deleted on exit. Configure encrypted disks/DB backups, restricted access, retention policy and lifecycle deletion before any public multi-tenant deployment. Secrets rotate through environment secret manager and provisioning CLI; no production secrets belong in Compose YAML or Git.
